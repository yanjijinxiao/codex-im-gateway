# 消息渠道授权状态设计

## 目标

账号管理页不把内部 sender 映射成“微信联系人 1”等虚构名称。授权前必须展示真实用户 Actor ID、来源 Conversation ID 和授权范围，让管理员明确自己在授权谁。该规则适用于微信、钉钉、飞书和企业微信。

## 状态

- `已有访问授权`：至少存在一个允许的用户或会话，提供“撤销授权”；不意味着所有访问者都已授权。
- `待授权`：收到未授权访问者的消息，完整展示用户和来源会话 ID，提供“仅允许此用户”；用户与会话 ID 不同时，可明确选择“允许整个会话”。
- `等待消息`：没有已授权记录，也没有最近访问者，提示先从对应渠道发送消息。

已有授权时的新请求显示在账号卡片的项目列表上方，使用真实渠道名称，不影响现有授权。当前仍基于最近访问者展示，不是持久化的待审批队列。

## 操作

授权前的确认框再次列出用户、来源会话和影响范围。用户授权只提交 Actor ID；会话授权只提交 Conversation ID，并警告群聊内其他成员也会获得访问权限。使用按钮所展示的 ID，不因后台收到新消息而改换目标。群渠道未获取 Actor ID 时不以 Conversation ID 冒充用户，不提供授权按钮。

“撤销授权”按账号撤销全部允许的 sender，执行前明确确认。所有操作继续使用现有本机令牌保护的授权 API，不改变持久化格式或访问控制规则。

## 验证

检查各渠道、已有授权后的新请求、缺失 Actor ID、HTML 转义、用户/会话范围的实际提交目标、取消确认及新消息竞争。长 ID 在窄屏下换行而非省略；浏览器检查不点击真实账号的授权按钮。
