# 渠道项目工作台方案

本文定义飞书、企业微信和个人微信如何围绕同一个 Codex 项目协作，并说明会话、任务、问答、计划和目标能力之间的状态边界。交互渠道优先使用原生卡片、按钮和表单；斜杠命令保留为确定性、可审计的底层能力。

## 1. 产品目标

已有会话以 `/sessions` 为主入口：分页列出全部可绑定的未归档会话，默认每页 30 个，`/sessions size 50` 可调整为 5-50 条并按聊天和用户持久保存；支持 `more`、`prev`、`page N`、`search 关键词` 和 `unbound` 筛选。`/session R1` 或 `/session 会话ID [--host 主机ID]` 可直接绑定；项目归属可以为空，不从工作目录猜测归属。

项目是可选入口，适用于新建会话、Taskboard 和问答模式。`/project` 选择时自动绑定并切换；旧 `/project add` 只是兼容别名。选择项目后，这些项目级操作使用该项目作为工作上下文：

- 会话模式继续或创建该项目的 Codex thread。
- 任务模式打开按项目目录映射的 Taskboard 项目。
- 问答模式仍在该项目目录工作，但通过只读工具优先检索项目绑定的 llm-wiki 知识库；项目未绑定时使用渠道账号配置的知识源。
- 计划模式和目标管理作用于该项目当前的 Codex thread，不成为第四种项目模式。

新建会话也不必先切项目：

- `/new`：在当前项目准备新会话；当前没有项目时提示选择，不自动选择列表首项。
- `/new P2`、`/new C1`、`/new --project 完整项目名`：使用 `/project` 的同一选择规则；未绑定项目自动登记，再切换到新会话。同名项目必须用编号。
- `/new --standalone`：在**本机**创建独立会话，每个会话有自己的持久工作目录，不继承当前项目或远程主机。
- `/session new ...`（以及 `/s new ...`）与 `/new ...` 完全等价，执行相同的权限和模式检查。

这些命令先创建 Gateway 会话记录，下一条普通消息才会调用所选 Codex 后端创建 thread。指定远程项目保留其 hostId，仅 App 后端支持远程执行。独立会话也需要 cwd；它位于账号状态目录的 `workspaces/standalone/session-*` 下，且显式标记 `projectBinding: "none"`，重启和首次消息都不能把它自动归入其他项目。目录不会在切换或结束会话时删除。

渠道端不要求用户记命令。能承载交互的渠道直接显示可点击控件；飞书收到卡片回调后原位刷新同一张消息，只有卡片过期或平台不支持更新时才新发卡片。文本渠道才显示等价的命令提示。

飞书还提供输入区的原生入口：将“快捷指令”配置为下表的命令值，或将机器人菜单项配置为同名 `event_key`。两种入口都会进入相同的受控动作和原生卡片流程；命令仅是飞书传输给 Bridge 的底层协议，不要求终端用户输入。

| 用户看到的快捷操作 | 快捷指令值 | 机器人菜单 `event_key` |
| --- | --- | --- |
| 打开工作台 | `/help` | `codex.workbench` |
| 选择项目 | `/project` | `codex.project` |
| 任务面板 | `/task` | `codex.taskboard` |
| 切换工作模式 | `/mode` | `codex.mode` |
| 计划/执行模式 | `/plan toggle` | `codex.plan` |
| 查看或设置目标 | `/goal` | `codex.goal` |
| 选择会话 | `/sessions` | `codex.session` |

机器人菜单事件需要订阅 `application.bot.menu_v6`，并在修改机器人能力后按飞书的应用发布流程生效。Bridge 提供受本地管理接口保护的同步入口：`POST /api/accounts/:accountId/sync-feishu-menu`。同步会保留既有的非 Codex 菜单、增量订阅菜单事件，并提交一个机器人默认能力的发布版本。首次同步前，飞书自建应用还需开通应用身份权限 `application:application:patch`；Bridge 会在缺少权限时返回明确提示，不会写入部分菜单配置。

## 2. 状态模型

| 状态 | 归属 | 作用 |
| --- | --- | --- |
| 当前项目 | 账号 + 发送者 | 决定新会话目录、可选会话筛选、Taskboard 映射和知识库绑定；不限制全局 `/sessions` |
| 当前工作模式 | 账号 + 发送者 | 在会话、任务、问答三种项目视图之间切换 |
| 渠道工作模式设置 | 渠道账号 | 决定可用模式、选中项目后的默认模式和项目未绑定时的问答知识源 |
| 会话 thread | 账号 + 回复作用域 + 主机 + thread ID；项目可空 | 普通协作、计划模式和目标的执行载体 |
| 问答 thread | 项目 + 知识库 + 发送者 | 与普通会话隔离，避免问答上下文污染开发会话 |
| Taskboard Issue | Taskboard 项目 | 任务状态唯一事实源，不复制进 Bridge 状态 |
| collaboration mode | Codex 会话 | `default` 或 Codex 原生 `plan` |
| goal | Codex thread | 通过 app-server 原生目标接口读取和修改 |

项目级模式切换不能改变项目目录，计划和目标只作用于当前绑定 thread。无项目会话仍可续聊、回看历史；App 后端支持跟随和介入，CLI 不支持的控制明确报错。

## 3. 项目与任务同步

项目和 Taskboard 不复制数据，而是按规范化后的绝对工作目录建立一对一映射：

| 用户动作 | Bridge 行为 | Taskboard 行为 |
| --- | --- | --- |
| 选择项目 | 保存当前项目并进入渠道配置的默认模式 | 尚不创建或修改 Issue |
| 点击“任务模式” | 使用当前项目目录解析 Taskboard 项目 | 返回该项目的任务概览卡片 |
| 选择 Issue | 校验 Issue 属于当前 Taskboard 项目 | 展示详情或绑定它的 thread |
| 新建任务 | 不复制任务状态 | 在当前映射项目创建 Issue |
| 切换项目 | 当前执行上下文切换；全局列表仍可发现旧项目会话 | 下一次任务查询改用新项目映射 |

任务模式不依赖已有 Codex 会话。因此用户可以先选项目，再直接查看或创建任务；只有“开始处理”一类需要 Codex 执行的操作才创建或绑定 thread。

Taskboard 始终负责 Issue 状态、版本和证据。Bridge 只保存当前项目、当前模式和当前 Issue 所需的会话关联，避免双向同步产生冲突。

## 4. 渠道交互流程

### 4.1 选择项目

渠道显示“选择 Codex 项目”卡片，每个项目是一个按钮。选择后，原卡片原位更新为该渠道已启用的同级入口：

- 会话模式
- 任务模式
- 问答模式

项目切换会立即进入渠道配置的默认模式，但不会自动创建 thread。这样既不会误触发 Codex，也不会把上一个项目的会话带入新项目。

### 4.2 会话模式

进入时优先恢复当前项目最近的普通会话；没有可恢复会话时才创建本地会话记录。卡片提供：

- 选择会话
- 切换计划/执行模式
- 查看或设置目标

普通自然语言消息随后进入当前 thread。Codex 发出的 `request_user_input` 会在飞书等渠道中转成原生选择卡片，并把用户点击结果回传给同一轮执行。

### 4.3 任务模式

渠道显示当前项目的原生 Taskboard 概览和详情卡片。根据 Issue 状态提供创建、开始处理、记录进展、阻塞、提交验收、通过和退回等按钮或表单。

所有变更都携带 Issue 版本；重复提交或版本冲突时刷新最新卡片，不盲目重试。阻塞、验收和退回所需的说明直接在渠道表单填写。

### 4.4 问答模式

问答模式优先使用当前项目绑定的 llm-wiki 知识库；项目未绑定时，使用渠道账号配置的默认知识源。渠道设置中的“项目”是该渠道当前已纳管的 Codex 项目：保存时以它的项目目录作为 llm-wiki 根目录校验，并创建或复用同目录知识库；“目录”则可选择独立的 llm-wiki 项目或目录。CLI 按“所选项目目录 → 显式引擎目录 → `LLM_WIKI_BIN` → 服务 `PATH`”解析，项目内支持 `.venv`、`tools/knowledge-base/.venv` 和 `skills/knowledge-base/.venv`。保存前必须同时通过状态格式和只读检索能力检测；修正同一目录的引擎路径时先验证再原子更新。Codex 的 `cwd` 始终是当前聊天项目目录，知识库仅作为只读检索来源。问答使用独立 thread，并按“项目 + 知识库”复用，避免和开发会话混用。

## 5. Codex 计划模式

计划模式是当前会话的协作属性，不是独立项目模式：

| 渠道操作 | Codex 行为 |
| --- | --- |
| 点击“计划模式” | 下一轮使用原生 `plan` collaboration mode |
| 点击“执行模式” | 下一轮恢复 `default` collaboration mode |
| 切换项目 | 不读取旧项目会话的 collaboration mode |
| 切换回原项目会话 | 恢复该会话自己的 collaboration mode |

渠道卡片始终提供相反状态的切换按钮，并保留“查看目标”入口。自然语言语义识别只会把高置信度意图映射到同一个受控动作，不能自由生成参数或命令。

## 6. Codex 目标

目标绑定到真实 Codex thread。没有 thread 时，渠道先引导进入会话或问答模式；有 thread 时：

- 没有目标：显示原生目标输入表单。
- 有活动目标：显示暂停、标记完成、修改和清除按钮。
- 目标已暂停或完成：显示继续、修改和清除按钮。
- 状态卡片显示目标、状态、token 使用、时间使用和可选预算。

目标的读取、设置和清除直接调用 Codex app-server 的 `thread/goal/get`、`thread/goal/set` 和 `thread/goal/clear`，Bridge 不维护第二份目标状态。

## 7. 自然语言与命令边界

默认入口是 AI 语义识别。渠道认证的 `senderId` 是可信用户身份；私聊或群聊的会话 ID 只负责承载项目、模式和当前任务状态，两者分别提供给分类器，模型不能猜测、替换或合并身份。分类器还会获得当前项目、当前模式、知识库和可选项目上下文。

一次识别可以返回单个动作，也可以返回最多四个有顺序的组合动作，例如“切换到项目 B，再查看任务”。所有动作都必须达到置信度阈值，并一起通过严格 schema、动作白名单和参数边界校验；任何一步不可信时整组都不执行，不采用已识别的部分前缀。执行阶段按顺序复用现有命令处理器，每一步开始前重新检查项目绑定和该渠道开放的模式，校验失败或处理器抛错时停止后续步骤。

以下命令是交互卡片的底层协议，也用于文本渠道、自动化和故障排查：

```text
/project                 选择项目
/mode session|task|qa    切换项目工作模式
/qa                      进入问答模式
/plan on|off             切换计划/执行模式
/goal                    查看或设置当前 thread 目标
/task                    打开当前项目任务面板
```

普通讨论、低置信度分类或识别失败会继续作为 Codex 对话，不进行关键词兜底匹配。

## 8. 安全和失败处理

- 每次任务操作都重新按当前项目目录解析 Taskboard 项目。
- Issue 必须属于当前映射项目，跨项目编号会被拒绝。
- 项目切换后，状态、目标、停止和后续 turn 都不能访问旧项目 thread。
- 卡片回调在渠道边界解析，只接受声明过的字段、长度和动作。
- llm-wiki 只暴露 `search` 和 `get_document` 等只读工具，不替换项目工作目录。
- Taskboard 和 Bridge 只接受本机回环服务地址，不把凭据放进卡片。

## 9. 实现位置与验收

| 能力 | 主要实现 |
| --- | --- |
| 项目和模式状态 | `src/state/runtime-state.ts` |
| 项目、模式、计划和目标命令 | `src/bridge/service.ts` |
| 当前项目到 Taskboard 的解析 | `src/bridge/taskboard-channel-context.ts` |
| Taskboard 渠道工作流 | `src/bridge/taskboard-channel-controller.ts` |
| 飞书等通用交互卡片 | `src/channels/action-card.ts` |
| 目标输入表单 | `src/channels/goal-form-card.ts` |
| Codex plan 和 goal app-server 调用 | `src/codex/app-server-runner.ts` |
| AI 语义路由 | `src/bridge/ai-channel-intent.ts` |

发布前至少验证：

1. 切换到项目 B 后，状态、目标和停止操作不能访问项目 A 的 thread。
2. 项目没有会话时，任务模式仍能打开项目 B 对应的 Taskboard 概览。
3. 会话卡片能用按钮切换计划/执行模式，并把选择传给下一轮 Codex。
4. 目标表单和状态按钮只读写当前项目当前 thread 的原生目标。
5. 飞书按钮和表单走原生交互，通用操作卡与任务卡都原位刷新；文本渠道才使用等价命令回退。
6. 自然语言低置信度或分类失败时继续普通对话，不误执行工作台动作。
7. 群聊组合指令使用真实发送者做访问控制、使用群聊会话保存项目状态，并按声明顺序执行。
8. 组合指令中任一步低置信度、模式未开放或项目不可用时，不继续执行剩余步骤。
