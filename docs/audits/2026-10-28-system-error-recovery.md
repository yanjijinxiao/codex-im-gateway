# systemError 条件恢复与故障核对

范围：仅 Gateway。系统状态恢复与任务执行结果分开管理，不将失败任务改成成功，不重复发送旧输入，不更换 session、主机或 IM 绑定。

## 原生能力验证

本机 Codex CLI 0.164.0 的稳定及实验协议未提供单独的 thread/reset RPC。真实隔离实验确认：对加载中的 systemError 直接 thread/resume，仍是 systemError；thread/unsubscribe 只释放本连接的订阅，原生运行时自行决定何时安全卸载。

可行路径是原生安全卸载后，对同一 threadId 调用 thread/resume，再读取该原生执行者的实际状态。不能杀共享服务、修改历史、归档再取消归档或发送空任务来制造正常状态。

真实测试使用全新 CODEX_HOME 与本机模拟模型，先产生真实失败轮次。测试专用 thread_unload_delay_secs=1 便于验证，生产配置不修改。确认 systemError → notLoaded → idle，历史逐项一致，恢复期间模型请求数不增加。这个实验不代表任意系统故障都能恢复，也不代表网络或账号故障已消失。

Desktop IPC 当前没有可用的无执行重载操作，CLI exec 后端也没有 app-server 状态操作。遇到这些所有者明确报告不支持，不通过私有 reader 或其他后端伪造恢复。

## 架构及约束

- Codex 适配器负责原生状态操作。仅处理同一会话、可信失败尾轮次、无在途执行/审批/孤立轮次的状态，先检查原生队列。队列接口不可用时禁止猜测并继续重载。
- 协调器负责状态机及持久化恢复记录：recovering、waiting、recovered、deferred、unsupported、failed、cancelled。它不是输入队列，不保存或重发用户提示词。
- 管理器提供主机、绑定、执行代际和客户端的有效期检查，并阻止已知提交未确认、队列执行或容量恢复与系统恢复交叉。
- 进展投影使用独立恢复卡，保存卡片检查点，显示原因、等待/恢复中和最终原生核对结果。原任务的失败卡及结果保持不变。/status 和 Web 会话/绑定视图显示同一恢复元数据。

同一 host/thread/failed-turn 合并为一次在途操作。原生仍加载且处于 systemError 时，只释放本连接订阅并进入 waiting，之后只读核对，不反复 resume 重置原生卸载计时。只在确认已卸载且仍是同一失败尾轮次时原生重载。其他所有者仍保留会话时，等待可能持续较长时间，不强行中断它。

一般失败按一分钟冷却；连续三次失败后冷却十五分钟。不支持的接口一小时内不重复调用。等待卸载每分钟只读核对，不刷重复进展。新的失败轮次、换绑、运行时重配置、取消或未确认提交会阻止旧操作继续。

恢复操作前持久化元数据；重启后对 recovering 记录只核对原生状态，不重复未确认的写操作。waiting 记录继续只读等待。可选恢复记录损坏时保留原文件、禁用自动写操作，不影响原始输入与绑定。记录容量有界，保留在途及等待记录，超出上限停止新增恢复。

进展投递有独立限时，IM 失败或挂起不会卡住原生恢复。投递前再次检查来源及实际客户端；延迟通知不能写到替换的会话。恢复未确认时新 IM 输入明确报“尚未提交到 Codex”。

## 测试覆盖

新增测试覆盖真实 CLI 卸载/重载及无额外模型执行；原生结果未改变时不能虚报成功；并发合并；冷却及重试；等待期间只读及重启；提交未确认、已有原生队列、容量恢复、活跃轮次和缺少可信尾轮次；换绑与客户端替换；坏记录及写前持久化失败；通知挂起；Desktop 禁止私有后端回退；失败任务卡保留；管理器到进展/Web 状态的实际接线；Web 输出转义；恢复未确认不得提交新输入。

隔离制品通过 scripts/release-local.mjs prepare 执行完整类型检查、全量测试与单独构建。实际测试数量、制品哈希和上线检查以对应发布目录的 manifest.json / verification.json 为准。上线保留授权、绑定和运行状态，失败回滚仅切换代码制品。
