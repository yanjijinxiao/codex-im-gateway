# Gateway 四层职责自检

基线：d742feb293281c386e8d6eb470bff2b381c90ff3。检查和修复范围为 Gateway，不含 Farming 和独立 Taskboard 实现。Gateway 对 Taskboard 的适配、公共配置、构建及安装集成纳入检查。

本轮阅读和隔离验证已完成，修复包含在本报告同一提交中。发布结果必须以该提交的隔离 prepare、seal 和切换后 verified.json 为准；这份报告本身不证明服务已上线，也不承诺不存在未知缺陷。

## 为什么此前通过测试仍有问题

从本轮实际复现看，问题集中在跨模块边界：原生执行、Gateway 绑定和页面状态各自成立，但异步结果到达时身份已经变化；可选查询与核心保存共用等待链；收到传输事件被误当作成功或长期保留；展示按钮使用会变化的列表序号。单一模块的成功路径测试不能覆盖这些组合。

这是检查覆盖与实现边界的问题，不能用“测试数量多”“模型上下文有限”解释成用户应该接受。此前检查不能视为完整性证明。本轮把阅读清单、原版失败反例、修改后回归及发布核验分开记录，防止再次把其中一项当成全部完成。

## 四层覆盖与证据

1. **架构**：先明确每个模块负责的事实、输入输出、所有权及不变量，再跟踪跨模块状态流。核对账号隔离、绑定代际、原生队列、审批来源、主机与项目身份、持久化提交及资源释放。
2. **模块**：检查正常、失败、并发、迟到、重复、重启、换绑、撤权及平台能力差异；疑点先隔离复现，再决定改动。
3. **文件和函数**：纳入的自有源码、测试及 fixture 逐文件阅读，沿函数调用核对责任边界。基线有 204 个 src 文件和 196 个测试/fixture 文件；新增 helper 与测试、修改后的文件另作最终定位和散列记录。函数索引用于定位，不等于每个函数都有独立测试或形式化证明。
4. **静态文件与配置**：HTML/JS/CSS、图片和引用，配置校验/默认值/迁移/序列化，manifest/lockfile，构建、安装、更新、发布脚本和当前/历史文档均纳入。8 张 PNG 实际查看并核对头部、尺寸及引用；历史截图不作为当前 UI 验收。

inventory.json 固定了基线 611 个 tracked 文件：纳入 475 个、排除独立 Taskboard 136 个，纳入文件均已有检查记录。**475 不等于 475 份逐行源码阅读**：lockfile v3（416 个包）按结构与 manifest 对照；两个大型历史生成 JSON 和历史 CSV 按全文件解析与字段/用途核对，不冒充逐行阅读或复用以前的代码覆盖。第三方依赖源码、生成 dist 不作自有源码审查。

reviewed-current.json 记录当前纳入文件的散列和代码函数位置，避免基线行号被误当成修改后的定位；不索引本审查目录自身，避免递归。evidence.json 保存选定日志的散列、运行数量和用途，区分原版反例、修复后验证、本轮中间实现发现的退化。candidates.md 保留中间误判和 fixture 修正，最终分类以本报告为准。

## 架构结论与责任边界

| 模块 | 应承担的职责和事实来源 | 本轮核对与处理 |
| --- | --- | --- |
| state/config | 有效操作与准入配置；持久化后发布尚无外部副作用的配置 | 完整运行字段校验，非法文件保留并失败关闭；主路由先写后发布 |
| server/accounts/admission | 账号隔离、准入与控制角色；启停持有资源的所有权 | 保存/启用配置共用串行事务和补偿；失败清理不短路；准入不等于控制或 IDE 访问 |
| bridge | 显式命令、普通消息、绑定与输入来源；控制变更属于发起它的上下文 | 查询前冻结绑定/项目/模式/发送者，提交前复核；未绑定也保留 detach 代际 |
| codex | 各适配器的原生能力与真实执行事实 | 修复摘要空白、历史失败/时间/归档范围、运行中 CLI 身份和畸形可选事件 |
| queue/recovery/follow | Codex 为唯一执行队列；Gateway 保存来源、回执与观察信息 | 未知提交不重发、来源不串、核对队列接续/恢复；精确所有者保留竞态，其余释放 payload |
| channels/interactions | 解码、错误边界、原生表单与实际投递回执 | claim 错误上报；chat_type 决定种类；原生按钮不重复复制指令，正文不变控制命令 |
| IDE | 主机/项目身份、浏览器鉴权与代理生命周期 | 离线根保留身份并拒绝缓存范围；本机别名仅本机核对；全部资源清理；轮询代际 |
| knowledge/webhooks/Taskboard adapter | 可选能力不能拖住核心功能或越过主机身份 | 远端不作本机目录知识库；首屏/保存与可选读取解耦；托管 origin 契约一致 |
| web/static | 当前表单拥有自己的回执/加载状态；静态完整、窄屏可用 | 开窗租约/提交单飞；旧结果不关闭新窗口；实际浏览器修正 IDE 控件裁剪 |
| build/install/update/release | 固定输入、完整制品、真实发行能力和代码回滚 | 普通构建清旧身份；源码部署不冒称 npm 更新；发布排他锁，隔离准备后短切换 |
| docs/config contracts | 说明与默认值、平台能力一致 | /sessions 默认 10、排序、steer/queue、远端 QA、原生卡片/fallback；历史方案明确标记 |

原生执行事实、Gateway 授权/路由事实和展示观察不应相互替代。控制租约复用已有绑定/角色/准入状态，没有创建第二份授权真相；可选观察器只有读能力、独立期限和有界在途键，不增加任务重试或任务超时。配置事务与 release 所有权分别围绕实际资源，不把所有异常都处理成“重新执行”。

## 验证结果与反例质量

最终工作版完整回归：**2040 项，2039 通过，0 失败、0 取消、1 Windows 平台专用跳过**；类型检查通过。显式设置 CODEX_NATIVE_QUEUE_TEST_BIN 启用原生队列集成，临时 CODEX_HOME、本机假模型/socket；不提交真实模型任务，不更改线上会话/绑定/授权。

新用例同时检查合法边界：IPv4 listener 可复用、active 归档模式原本通过、未知渠道种类不猜、完整最终答案不被诊断预算截断、同一会话接收竞态保留、其他线程不能扩大保留范围、旧原生卡片拒绝但手动命令兼容。用挂起/迟到 Promise、故障存储和真实假子进程复现，不只断言源码字符串。

两个本轮实现中的退化也留有失败证据：release fd 在 fstat 故障时关闭，以及显式模型值与数字/default 命令语法冲突。后两个选择用例在原始基线本来通过，不能算原始缺陷。fixture 的 VM 全局、SDK shape、目录别名或错误路径等中间错误均在 candidates.md 区分，不冒充产品故障。

多轮子集有重叠，**不能把次数相加宣传覆盖数量**。最后仅移除测试 fixture 中被覆盖的重复 packageRoot 字段并单独复验 updater；发布 prepare 在固定提交重跑类型检查、完整回归和隔离构建。现有全部测试通过不是未来可靠性的充分保证。

## 已知限制与未替代的验收

- Hub 后台全量轮询仍为有界批调度，下一批可能被慢读取拖后。隔离屏障证实健康结果本批立即发布、定向 synchronize 不等其他订阅；未宣称消除所有后台延迟。
- 诊断有预算，完整 rollout 单记录仍需组装；本轮不是全进程内存总上限或长期负载证明。畸形未完成上游状态仍需运营观测。
- 可选探测不取消不支持取消的底层调用，超时后共享同一在途工作；容量满时明确降级，不启动无限替代探测。
- Web 防旧开窗/重复提交，不撤销已提交写入，也不承诺编辑同一开窗字段能取消前次请求。
- Windows npm 用平台注入测试；Windows 实机、真实飞书/钉钉服务端交互、手机 IDE 网络/渲染仍需实际验收。本机浏览器仅验证页面布局与基本加载。
- 原生协议及第三方服务后续升级可能改变能力。systemError 恢复须确认精确会话、原生能力与接收事实，不能通过重复提交未知任务“恢复”。
- 发布核对权限/绑定/制品；关闭服务仍可能影响私有客户端持有的执行。代码回滚不恢复旧权限文件、不重放任务。崩溃遗留 release.lock 需核实所有者已退出后清理。

后续修复应继续先明确事实来源和所有权，保留原版反例及正向/并发/失败场景，发布以固定提交和实际核验为准。
