# 恢复进展卡的停止命令复制框

截图圈出的是停止任务入口 `/stop`，不是说明性路径或展示用代码。上一轮压缩排版将它误当成普通命令参考，改成了行内代码；对应测试也错误地断言不能出现复制框。这是展示要求判断错误，不能归因于钉钉偶发渲染。

本次只恢复操作控件：使用现有 copyBlock 生成独立 text 代码块，块内只有完整 `/stop`；说明保留在块外，并明确复制不会发送。正文继续使用紧凑布局。动态正文和静态操作页脚的职责边界不变，不增加执行回调、不自动发送停止指令，也不改变权限判断、会话或原生任务。

回归核对运行、等待回答、等待审批、恢复、状态待确认、回复预览、长代码/表格未闭合、页脚 IDE 链接变化、恢复已有卡片及最终结果。通过真实 HTTPS/SDK 适配器的状态模型验证正文不包含停止命令、静态区始终包含唯一的精确命令块，普通进展帧不重写未变化的静态控件，最终结果不残留停止入口。该模型不能替代钉钉客户端视觉验收。

先修改需求断言，再在原实现上复现：25 项中 11 项因没有命令块而失败；记录 /private/tmp/gateway-stop-copy-baseline-20261029.log。修复后相关 129 项通过，覆盖复制组件自身的惰性行为；记录 /private/tmp/gateway-stop-copy-fixed-20261029.log。全量回归与部署结果以对应独立 release manifest 为准，部署继续遵守原生任务所有权门禁。
