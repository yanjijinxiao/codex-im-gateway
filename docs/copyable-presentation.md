# 按用途提供复制控件

判断标准是**用户是否需要把精确内容发回或带到另一个页面**，不是文本是否长得像路径、ID、命令或选项。复制不能执行、选择、提交或批准。

## 呈现边界

| 内容用途 | 呈现方式 | 项目中的例子 |
| --- | --- | --- |
| 供核对和阅读 | 普通文字或代码样式，不附复制框 | 项目目录集合、执行主机、状态、已登记个人 ID、命令语法参考 |
| 在当前页面操作 | 原生表单、下拉框、按钮，不重复提供标签或枚举值的复制框 | 管理页配置、目录核对对话框、任务状态及优先级菜单 |
| 需要发回或跨页面回填 | 精确完整值的独立复制控件，说明放在控件外 | 网页授权命令发到 IM、未登记个人 ID 填到管理页、通知接收会话 ID 填到配置 |

同一字段的用途可以随状态变化：首次登记个人身份需要搬运 ID，已经登记后的身份查询只需展示。目录核对是阅读和批准范围，不需要把目录发回，始终不加复制框。

## 网页：生产端显式声明，不猜测 DOM

管理后台、IDE SSR 与任务面板共用 `src/web/copyable.js` / `copyable.css`。公共层只扫描 `data-copy-purpose="reply"`（发回答案）或 `data-copy-purpose="transfer"`（跨页面搬运）；不再扫描普通 `input`、`select`、`code`、列表或菜单。需要搬运的展示值可同时声明 `data-copy-output` 精确值和 `data-copy-label` 用途说明。

生成独立控件时必须指定用途：`window.gatewayCopy.field(label, value, { purpose: "reply" })`，SSR `copyField` 使用相同契约。`rows` 可选 1 或 2。不明确用途的调用不能生成控件。敏感区域继续使用 `data-copy-ignore`；隐藏、密码、文件、复选和单选输入不增强，CSRF、浏览器证明、Cookie、授权票据不能成为待回填内容。

只读框、复制按钮与反馈分离；复制事件阻止所在行、链接、表单的默认动作，不替换原输入节点。剪贴板不可用时保留并选中精确值供手动复制；API 返回只显示「已请求复制」，不读取用户剪贴板，也不假称已核验粘贴。IDE 等待页在操作控件期间暂停刷新。

任务面板共用层不再给原生菜单选项重复加复制按钮；它自身明确提供的「复制议题 ID / 标题 / Markdown」仍是用户主动选择的复制功能，保留。

## IM：可发送答案与语法参考分开

`src/channels/copyable.ts` 的 `copyBlock` 和幂等 `copyableChoices` 只用于真实回复或必要搬运。每个完整答案独占一个代码块，解释和选项标签在块外，不混入编号、多个命令或秘密。

公共选择卡为 IM 回复保留完整命令，隐藏回调 ID 用 `copyValue` 转为当前真实编号，例如 `/session R1`；不能把普通标签或内部枚举当答案。任务表单在原生控件里直接填写，不再附 `urgent` 等不能独立发送的内部值。文本降级需要用户编辑时，明确称为模板，给出完整命令及需替换参数。`/help` 的语法目录仍为参考文本，另列实际可直接发送的导航命令，不把带方括号、竖线和虚构编号的语法包装成现成答案。

会话详情、分页、排队取消、跟随设置、错误恢复等明确要求发送的下一步，在生产消息的调用处声明完整命令；不对任意模型输出、用户文本或历史记录做正则猜测并改写。IM 长内容仍使用保留围栏的 `resultPages`。

Bridge 模型提示同步区分以上三类用途；旧提示仍能从历史展示中剥离。展示变化不修改命令解析、审批资格、权限范围、绑定、去重或提交语义。

## 验收

先验证真实目录核对页：目录正常显示、没有复制框；只有需要发到 IM 的权限命令可复制。点击复制不批准浏览器，原页面和原申请保持不变。再验证管理页原生输入及选项没有多余控件，必要的跨页面值仍能独立复制；任务面板使用真实 React 页验证状态菜单直接操作，其主动复制功能仍可用。授权快捷跳转继续受现有 Cookie / proof / 过期和撤销边界约束。
