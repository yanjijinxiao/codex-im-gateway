# 项目 Web IDE

本功能默认关闭。仅为已有项目关系的受管 session 提供 code-server 入口，不为无项目、QA session 推断项目，不通过访问 IDE 创建、介入或停止 Codex 轮次。

## 配置与使用

1. 项目主机需有 Node 和已登记的 SSH 连接。IDE 的进程连接、转发连接与 Codex 控制连接互相独立。本机 code-server 不承担远程文件系统挂载。
2. 在 Gateway 本地管理台的「Web IDE」页选择允许的项目主机。已有 code-server 可填写绝对路径；缺失时可勾选自动安装并保存，再点击「检测 / 安装 / 重试」。无需另设 IDE 密码。
3. 配置 IDE 端口与浏览器入口。本机可用 HTTP 回环地址。内网 / VPN 可在管理页启用「由 Gateway 直接提供 HTTPS」，选择当前已分配的精确 IP，生成 / 复用自签证书后保存。无需另装反向代理，也无需域名。已有 HTTPS 反向代理可不启用内置 TLS，继续转发 HTTP 和 WebSocket 至回环的 **IDE 专用端口**，并保留原始 Host；不能将整个 Gateway 管理端口公开。
4. 在会话页面选择 session，点击「Web IDE · 授权并信任」；这会授权访问并允许精确目录的任务、调试和扩展执行。也可在 IM 中使用 `/ide` 或 `/ide status`。有可用入口时，最终答复（包括已有的参与者 @ 结果卡）附带同一项目入口。支持 Markdown 的渠道显示「打开项目 Web IDE」短标签，目标地址与授权范围不变；不支持 Markdown 的纯文本渠道可能显示其源文本。生成链接不会启动 IDE。
5. 本机管理页打开时，Gateway 用一次性表单 POST 交接授权，不把票据放进 URL。从 IM 链接进入的新浏览器显示 6 位识别码，可由本机管理页批准，或按下节使用已登记管理员的钉钉私聊跨设备批准。两种入口共用审批服务，均需核对识别码、项目、主机及精确目录。原浏览器每 3 秒自动检查并继续，也保留手动继续入口。公开链接和识别码本身都不是授权凭据。
6. 批准并信任及打开时均核对原生 cwd 和项目归属，打开时解析主机上的真实目录并启动／复用实例。Desktop 实时 IPC 缺失 projectId 时，通过与 App/catalog 相同的 Desktop 项目登记适配器规范化，不把字段缺失当作项目变更；明确无项目或归属不一致仍拒绝。原生目录读取失败时不回退到猜测目录。

单文件夹项目直接以实际目录作为 VS Code 工作区，无需在项目中生成 `.code-workspace`。浏览器中的 VS Code Web 信任记录不是跨浏览器的主机授权。选择「授权并信任」后，Gateway 记录已核对的 canonical 目录，并为它启动独立信任策略实例，使用 code-server 官方的会话级 `--disable-workspace-trust`，消除第二次浏览器信任确认。它不修改全局 VS Code 设置，不写入 `safe.directory=*`；「仅批准访问」仍保留 Restricted Mode。

信任绑定到 owner/host/project/session 和核对过的 canonical 目录；打开时重新核对，目录改变不沿用旧授权。受信任实例的工作台入口拒绝通过 `folder`、`workspace` 或 `ew` 参数切换到别的项目。可信与仅访问策略使用不同实例及数据目录；升级后如需所选扩展，应对可信实例点击「准备扩展」。此限制不是 OS 文件系统沙箱：终端和扩展仍具有运行用户的权限。

配置按差异应用：新增主机和重复保存不重启已有入口、不停止已有 IDE，也不撤销无关授权。停用主机、改变该主机的可执行文件或修改 Profile 时，只停止并撤销受影响主机的 IDE 与授权；改变入口安全边界时，只关闭并撤销对应入口的连接与授权。请先保存受影响的编辑内容。停止 IDE 不停止 Codex 任务；解绑 IM 也不删除项目文件。

## 内网 / VPN HTTPS 与证书

### 按项目主机分开入口

管理页启用固定远程 HTTPS 转发后，`routing: "per-host"`：维护入口必须为 `http://127.0.0.1:<port>`，只能在 Gateway 所在电脑使用；远程项目使用各已登记 SSH 主机的 `access.publicOrigin` 固定 IP HTTPS 入口，或下面的共享入口。本机项目还可配置独立直连入口。未配置或未连通的入口不回退到其他地址。入口 ID 保持 account/session 关系不变，但 origin 变化后需要重新批准浏览器一次；使用固定远程入口时，Mac 的 VPN 地址变化只影响转发连接，不延长或撤销原始 15 天授权。

远程 `access` 明确区分三个值：`publicOrigin` 是浏览器访问的固定 IP 和外部映射端口，`bindAddress` 是远程进程实际所在主机 / 容器的精确网卡 IP，`port` 是映射对应的内部监听端口。固定映射必须由环境预先提供；产品不调用 Docker、不重建开发容器、不修改 sshd、不自动使用 sudo。不要将 SSH 映射端口当作 Web 端口，也不要填通配监听地址。

Gateway 为各远程入口在本机私有回环端口终止 TLS，使用原 CA 按固定公网 / 内网 IP 签发叶子证书。独立 SSH 连接建立 owner-only 远程 Unix socket 反向转发；远程临时进程只将精确监听地址收到的原始加密字节转发到该 socket，不提供文件、终端、code-server 直连或 Gateway 管理 API；它不是额外的 OS 用户沙箱。CA / TLS 私钥、浏览器授权 Cookie 和一次性票据不复制到远程转发进程。每个入口均执行 Host、Origin、CSRF、HTTP / WSS 检查，并只接受属于本机或该远程主机的项目；授权文件按主机隔离，范围仍包含 owner/project/session/canonical 目录。

入口控制器与 IDE 进程生命周期独立：转发失败只关闭自身连接并以 1 至 30 秒退避自动重试，不重载配置、不停止 IDE 或 Codex 任务、不修改绑定和授权。后台通过真实固定 HTTPS 入口探测后才发布「已就绪」，不是仅检查 SSH PID；各主机独立显示状态，远程离线不阻塞本机入口、管理页或 IM。停止 Gateway 会停止其转发；Mac 关机、休眠或失去远程网络时，远程入口也暂不可用，恢复后自动重连。转发恢复不代表所有终端会话都能无损恢复。

### 手机与电脑共用一个项目链接

在固定转发模式下，管理页「共享 HTTPS 入口」选择一个已启用并配置 `access` 的远程主机，保存为 `sharedIngressHostId`。这是**浏览器发布入口**，不是项目执行主机：默认所有已启用主机的 session 发布该固定 HTTPS origin 加原有 `/workspace/<id>` 的唯一链接；显式配置 `localAccess` 时，仅本机项目使用独立直连入口。本地项目的 code-server、文件、Git 和终端仍运行在 Gateway 所在 Mac；远程项目仍在实际项目主机运行，不复制源码。没有共享入口的旧配置继续按主机发布，不静默扩展访问范围。

Mac 的 `127.0.0.1` 监听保留供本机维护，不再作为共享模式的 IM 链接；共享入口不就绪时不回退到回环或 VPN 地址。现有远程入口的 origin、项目 ID 与授权文件不变，因此原远程项目授权不因开启共享路由而改变；仅在回环 origin 上持有的本地项目浏览器授权不会跨 origin 迁移，需要在新 HTTPS 入口批准一次。授权仍绑定原浏览器、account/session/owner/项目主机/目录，其他项目不会继承权限。跨设备审批按申请 ID 和项目 ID 定位原入口，不能用同项目的本机申请替换手机申请。

固定入口只转发 IDE 数据面，不暴露管理后台，不给远程转发进程分发 CA 私钥或浏览器凭据。它依赖 Mac 在线以及 SSH 连通；后台健康检查只能证明 Gateway 发起的探测成功，**不能代替手机公司 VPN 的路由和端口连通性验收**。首次应在目标手机核验固定端口、证书信任、钉钉审批、项目目录、编辑和终端；自签 CA 不会自动写入设备信任库。

### 本机项目直接使用自己的内网 / VPN IP

在分主机模式下，管理页「本机项目 · 内网 / VPN 直连」可显式配置 `localAccess: { publicOrigin: "https://<本机IP>:8790", bindAddress: "<本机IP>", port: 8790 }`。IP 和端口必须与 HTTPS origin 精确对应；地址必须是 Gateway 当前已分配的非回环接口地址，不接受全网卡监听。配置同时保留维护回环和远程转发监听，入口选择只覆盖 `hostId: "local"`，不改变远程项目的入口、授权和执行位置。历史共享链接仍可通过原入口使用，但只发布新直连链接，不同时发送两种链接。

新监听仍是 Gateway 的 IDE 数据面，TLS 在本机终止，使用已有 CA 自动准备和续签对应 IP 的证书；管理 API 不对外提供，code-server 仍仅监听私有 Unix socket。直连授权独立保存在 `ide/authorization-local-direct.json`，不可与回环或共享 origin 互用；第一次切换需批准新浏览器，不自动迁移旧 Cookie。关闭、重绑直连只撤销其授权，不中断未变更远程入口。新增直连端口被占用时单独报错，修复后重新保存可重试；新增配置的地址未分配时拒绝提交。已有直连地址离线不会阻塞其他远程主机热接入。

VPN IP **不等于固定 IP**。接口失去该地址时，管理页显示离线，停止发布直连链接，不回退到共享或回环地址。更换地址需明确配置并重新批准；旧 IP 链接无法自动重定向。证书不会绕过 VPN 入站限制，必须从手机验证，不以 Gateway 自连或 Mac 到远程 SSH 的单向连通代替验收。

### 需要用户复制的内容

已批准的浏览器打开同一个项目入口时，已运行的 IDE 直接重定向到 code-server；冷启动由 nonce 脚本自动提交原有带 CSRF 的同源启动表单，不再要求点击第二个「打开 Web IDE」按钮。GET 本身不启动进程、不提升目录信任。自动安装进行中时显示进度并自动重试；扩展准备警告仍在管理页保留，不再阻挡进入可用编辑器。未授权、过期、撤销、项目或 origin 改变时仍执行原授权流程；不会因为 IM 中曾批准其他浏览器就绕过本浏览器鉴权。

外部 IM 链接的首跳可能不携带 `SameSite=Strict` Cookie。首跳未验证身份时先返回 nonce 保护的「正在核验已有授权」页面，立即同源导航到固定项目路径的 `?auth_check=1`，不等待授权页的 3 秒轮询。复查仍逐次验证 Cookie、项目 scope 和有效期；只有确实未授权才创建申请并显示批准页。查询标记只区分呈现阶段，不携带令牌，也不能授予访问、目录信任或触发 IDE 启动；不放宽 Cookie、Origin 或 CSRF 规则。禁用 JavaScript 时保留手动核验链接，且不形成循环。

IDE 授权等待页直接显示项目、执行主机、精确目录和三种权限。用户核对后，复制所选 `/ide trust|access|deny 十二位随机编号` 命令，在已登记个人身份的机器人私聊发送一次即可处理，不再要求默认流程的第二条确认命令。浏览器识别码及每种选择各有独立只读复制控件，管理页识别码和个人 ID 复用同一控件；成功有反馈，剪贴板受限时可长按短命令复制或直接输入。按钮不提交表单、不发送 IM，也不批准访问。等待页使用 nonce 限定脚本，复制和手动选择期间暂缓自动刷新；无 JavaScript 时可通过「批准后继续」手动检查。

管理页、IDE 中转页面和任务面板现在共享 `src/web/copyable.js` / CSS 的复制层。动态出现的输入框、ID、代码、Markdown 列表选项、单选/复选项和菜单选项会独立获得复制入口；下拉框还可展开「逐项复制选项」。不替换现有输入节点，不复制隐藏字段、密码、文件输入或可编辑富文本内部结构；复制操作只写剪贴板，不能触发所在行、链接、表单或审批。点击后始终保留精确只读框，内嵌浏览器限制程序化剪贴板时可手动选择复制。IM 问题、审批、配置选择及任务卡片在公共呈现层为每项命令或选项生成独立代码块；Bridge 给模型的呈现指令也要求把所有需要用户回填的内容和每个选项分别放进独立块，说明文字留在块外。详见 [统一复制呈现约定](./copyable-presentation.md)。

浏览器命令由统一审批服务在首次展示时创建随机 48 位短编号，绑定原申请 ID、入口、项目完整快照、Gateway 渠道账号、平台及机器人应用 ID；不是六位公开识别码或可访问 IDE 的 bearer 凭证。轮询复用同一编号，不能将旧编号重新绑定到变化的目录或其他申请；复制出的数据不能修改服务端快照。最终只接受被对应渠道确认是私聊的原始命令，并重新核验该渠道账号当前已登记管理员身份。命令可由该账号的已登记个人管理员处理，普通用户、群 ACL、模型输出或转发链接不构成审批资格。

旧 `/ide auth 六位识别码` 核对流程保持兼容；审批展示服务暂未就绪时也可回退到该流程。旧流程仍提供临时「确认复制面板」，其编号额外绑定发起核对的个人身份。该面板只允许 GET，不签发或交换 cookie，不自动刷新，不提供提交表单；链接预览、转发或爬虫均不能批准浏览器。所有决策统一执行每个人每分钟 20 次限流、原申请 5 分钟期限、并发去重、单次消费、异步真实目录核验前后重检，以及原浏览器私有 proof 交换。处理后、过期、重启、管理员或入口切换均不会恢复旧命令。已签发的 15 天浏览器授权仍持久保存，不受短期命令内存状态影响。

共享入口模式仍保留兼容；不会在升级时静默修改现有网络策略。普通重连及新增项目主机不会撤销旧授权或停止已有 IDE。固定主机、容器或端口映射本身被撤销时，需要在管理页更新相应映射配置；自动重连不替代基础设施的稳定性保证。

### 主机热接入

新机器的受管项目登记后，在本机管理页刷新主机清单，显式启用该主机；需要自动安装时另行勾选授权。保存即增量生效，不重启 Gateway、IM、原生 Codex 任务或已有转发器。共享入口模式下新项目主机不必配置 `access`：浏览器仍使用原固定 HTTPS 入口，Gateway 通过独立 SSH 连接访问项目主机的私有 code-server socket，无需为新机器新增 Web 端口。发现 session 不自动启用 IDE、不自动批准安装，更不自动批准浏览器。

`IDEEndpointManager` 以已应用配置与目标配置协调资源。入口指纹只包含监听及转发的网络身份，允许的项目主机清单可原地更新；项目进程按主机独立取消和停止。新增主机不可达或新入口启动失败，不影响其他健康入口，状态单独显示并可重试。关闭自动安装仅取消该主机尚未完成的安装，不关闭其现有 IDE。Profile 是所有主机共用基线，因此更改 Profile 会影响全部已启用主机。

受 mutation token / Origin 保护的配置提交串行执行，校验通过后先持久撤销受影响范围，再提交新配置；撤销记录写盘失败则拒绝提交，重试仍需完成持久化。增量撤销涵盖浏览器 Cookie、一次性票据、待批准及已批准未兑换的配对，以及尚在核验真实目录的审批。受影响主机的代际栅栏阻止过时的异步启动完成；禁用后重新启用不会恢复旧授权。正常关闭 Gateway 仍保留未过期的浏览器授权，不自动重放安装或恢复项目进程。

管理页的证书生成只准备文件和填写表单，不立即改变监听。保存配置才会启用所选精确 IP 的 HTTPS；拒绝 `0.0.0.0` / `::` 全网卡监听。Gateway 管理台保持回环 HTTP，code-server 仍使用私有 Unix socket。VPN 的路由、客户端隔离和入站防火墙限制不由证书解决；必须从实际访问设备验证连通性，不能只测本机自连。

本地 CA 和按 IP 签发的服务端证书保存在状态目录 `ide/tls/`，目录 0700、私钥 0600，不在项目源码内。CA 有效期 5 年、叶子证书 365 天；启动及每 12 小时检查，在叶子证书剩余不足 30 天时使用原 CA 续签并热加载，不中断已有终端或撤销浏览器授权。CA 不会静默更换，损坏、过期或有效期不足以签发新证书时显示错误，需要所有者处理。自备证书也可填写绝对证书 / 私钥路径，其续期由外部工具管理，应用配置或重启后加载。

每台访问设备需自行导入并信任公开的 CA 证书，核对管理页 SHA256 指纹；仅点击「忽略证书警告」不保证 Service Worker / Webview 可用。Gateway 不安装系统根证书、不关闭 TLS 校验、不运行浏览器安全绕过。管理页仅提供 CA 公共证书下载，CA 私钥与服务端私钥不能发送给客户端；请保护本地 CA 私钥，信任该 CA 是独立的设备安全决策。

监听启动前检查证书有效期、入口主机名 / IP、证书私钥匹配、私钥权限。只增加 HTTPS 传输，不绕开原有 Host / Origin / CSRF、项目授权和 WSS 校验。HTTPS Cookie 带 Secure。首次从回环 HTTP 改为 VPN HTTPS 时，浏览器 origin 改变，旧授权按安全边界失效，需要重新批准一次；新授权仍为 15 天并跨重启保存。以后同一入口的叶子证书续期不改变授权。

如果 VPN 地址改变，原地址的链接及证书不能自动代表新地址；重新选择 IP、准备证书并保存。原 CA 可继续复用，但入口 origin 改变后仍需重新批准访问。

## Profile

网页可编辑允许迁移的设置白名单，并从已核对的 Open VSX 候选中选择扩展。配置写入新实例，不覆盖项目 `.vscode`，也不复制桌面 VS Code 的登录态、扩展数据库或密钥。新 Profile 产生独立数据目录；旧目录保留。仅生成入口或最终通知不会安装扩展；获授权浏览器打开实例时，先使用同一组 `--user-data-dir` / `--extensions-dir` 查询实际安装清单，只安装缺失项，并再次查询核验（不能只信安装退出码）。也可在会话页点击「准备扩展」提前安装，需要先停止该实例。同实例并发打开复用一次准备；不同主机、用户、目录、Profile 和信任级别仍隔离，不复制或共用扩展目录。失败时打开流程允许降级进入编辑器，但管理页明确列出未就绪项及重试方式；显式「准备扩展」则返回失败，不报假成功。没有自动更新或卸载扩展。

运行时缺省设置独立于 Profile 身份。Chat 所在的次侧边栏默认 `workbench.secondarySideBar.defaultVisibility: "hidden"`，新实例初始化时应用，旧实例只补缺失项。迁移保留 JSONC 注释、尾逗号和显式用户值，不覆盖用户布局、其他设置或授权；无效/并发修改的设置文件不覆盖，并显示警告。已被浏览器保存为展开的旧布局可能需手动收起一次；这不是永久禁用 Chat。此设置可在 Profile 显式覆盖。

缺省视觉外观是 Dark 2026、Seti (`vs-seti`) 文件图标、Default 界面图标、`Menlo, Monaco, 'Courier New', monospace` 字体族、12px 字号、18px 行高、normal 字重、关闭字体连字、标签页换行。主题和图标来自已固定 code-server 的内置资源，不复制桌面缓存数据库、用户令牌或整个 VS Code 配置。字体由打开浏览器的设备解析，远程 Linux 主机不安装或传输 Menlo；设备没有该字体时按备用族回退。现有实例启动时只补缺失外观项，已显式设置的主题／字体保持不变，项目级设置仍按 VS Code 规则覆盖。白名单可显式覆盖以上外观值；字号、行高、字重与布尔开关由服务端校验。仅升级缺省外观不改变实例身份、扩展目录或浏览器授权。

不支持将 Microsoft Remote SSH、Containers、WSL、Pylance 或微软 C/C++ 扩展直接搬入。平台包与工具链需按所在主机验证；注册表有发布包不等于语言功能已实测。

## 状态和隔离

### 跨设备审批

1. 首次在对应机器人的钉钉私聊发送 `/ide identity`。在 **运行 Gateway 的电脑** 管理页「Web IDE → 授权管理员」选择该渠道账号，核对并登记返回的个人 ID；不要填写群 ID。此操作需要本机管理页 Origin 和 mutation token，不接受远程 IDE 入口或普通 IM 添加管理员。登记并不直接批准浏览器。
2. 其他设备打开项目 HTTPS 入口，核对授权页上的项目、主机、目录及权限。请求不要求当前机器人私聊绑定 session，不调用 Codex、模型意图分类或原生队列。
3. 从授权页复制一种短命令，在对应机器人私聊发送一次即处理，无需先发 `/ide auth` 或再等一轮卡片。`trust` 同时允许精确目录的任务、调试及扩展；`access` 不自动信任目录代码；`deny` 拒绝。旧的 `/ide auth` 及 `/ide confirm` 兼容语法不恢复过期确认，也不省略本人鉴权。
4. 仅原申请浏览器持有的 HttpOnly 随机证明能兑换 15 天授权。IM 不接收浏览器 token、Cookie、一次性网页登录票据或私有证明。一次确认编号绑定对应渠道账号、机器人应用、原申请及完整范围；旧核对流程还绑定发起核对的具体个人。复制编号不能取得管理员资格，也不能跨渠道账号或机器人使用。

`IDEApprovalService` 统一维护管理员与待确认决策；本机网页和 IM 控制适配器共享提交边界。管理员独立于聊天白名单、群 ACL、session 角色及绑定，持久记录在 `ide/approvers.json`（0600）。身份绑定 Gateway 渠道账号、平台、机器人应用 ID 和人类用户 ID；同名渠道换机器人不继承资格。首次仅钉钉适配器提供明确的私聊/群聊信号；其他未提供该信号的渠道拒绝 IM 审批，不能通过用户 ID 与会话 ID 相等来推断私聊。

管理员仅批准本渠道账号关联的项目，不能跨账号查询申请。识别码查找限每身份每分钟 10 次；多入口码冲突拒绝模糊匹配，提示刷新，不批准任意一项。所有确认有原申请 5 分钟期限，单次提交，处理中的重复确认拒绝。异步真实目录核验结束后重新检查管理员资格、申请和项目范围；撤销资格、配置切换、目录或原生项目变化时拒绝过时审批。

移除管理员立即使其待确认操作失效，但不静默撤销已经签发的浏览器授权；需要时在本机页面另行撤销浏览器登录。已签发授权仍按原 15 天有效期跨重启保存；短期申请和确认编号不跨重启恢复。审计记录操作者和项目入口，不记录浏览器证明、Cookie 或识别码。审批不改变 session 绑定。远程等待页不再提供指向访问设备自身的 `127.0.0.1` 管理链接；本机回环 IDE 的跨设备可达性不在本功能范围。

- 专用配置：Gateway 状态目录的 `ide/config.json`，目录 0700、文件 0600。旧版密码哈希读取时忽略、保存时移除；不再提供密码登录接口。
- 入口引用：`ide/workspaces.json` 仅记录 account/session 引用，不接受浏览器指定任意 cwd、主机或上游 URL。每次访问重新校验受管项目关系；移除关系后旧入口不可继续建立连接。
- 本机 IDE 数据：Gateway 状态目录的 `ide/instances/<id>`；远程 IDE 数据：远程用户的 `~/.local/share/codex-im-gateway/ide/<id>`。实例身份包含 Gateway 安装、所有者、主机、canonical cwd、provider 和 Profile；两个 session 指向同一工作树时可复用。
- code-server 只监听私有目录中的 Unix socket（0600），远程通过单独的 SSH Unix socket 转发接入。内部 `auth:none` 不暴露 TCP 端口，访问边界由 Gateway IDE 服务承担。
- 授权由本机 Gateway 的 Origin / mutation token 边界签发：一次性票据 60 秒，浏览器配对申请 5 分钟，新签发的项目范围会话 15 天。有效期由服务端统一常量提供，API 页面说明、Cookie 和持久化到期时间一致；旧授权保留原始到期时间，不静默续期。配对使用 HttpOnly 随机浏览器证明，不能凭复制的链接、申请 ID 或识别码兑换授权。
- 已批准会话以 token 哈希、作用域、精确目录/信任选择和原始到期时间保存到 `ide/authorization.json`，目录 0700、原子写入文件 0600，不保存原始浏览器 bearer token。Gateway 正常关闭/重启保留会话，不延长到期时间。短期一次性票据和待批准申请不跨重启恢复；损坏文件拒绝访问，不覆盖原文件，也不阻断 IM 启动。
- 项目会话使用 HttpOnly、SameSite Cookie，HTTPS 入口增加 Secure；Cookie 按入口独立命名，授权还绑定主机、目录及项目身份。打开及退出要求 Origin / CSRF；WebSocket 验证授权和当前入口，并在撤销、超时或停止实例时断开；存量连接周期核验关系变化。
- HTTP／WS 代理不转发 Gateway Cookie、Authorization、管理请求 Token 或用户伪造的转发头，也不采信上游覆盖 Gateway 的登录 Cookie。
- 单个 Gateway 最多同时准备／运行 8 个 IDE 实例。启动、目录读取和健康探测有超时。IDE 配置或监听失败不能终结 IM／Codex 服务，网页单独显示错误。

## 安全边界与首版限制

这是 **单所有者、完整开发权限** 的 IDE。获授权的浏览器及其扩展、终端可以访问运行用户具备权限的文件和网络，打开某个目录不是 OS 沙箱。只有 IM 会话参与权不等于有开发终端访问权；不要批准他人的浏览器申请。多用户部署应另外提供独立 OS 用户、容器或 VM 隔离。

不提供公网证书／域名自动部署、不自动安装远程系统依赖，也不在 Gateway 重启后自动恢复 IDE 进程。浏览器在原授权有效期内可在重启后直接进入项目并按需重启 IDE；原生 Codex 任务与 IM 绑定不变。退出、撤销全部及受影响范围的配置变更会持久化失效记录并断开相应连接；新增主机不执行全局撤销。旧版仅存在内存中的授权无法迁移，升级后需重新批准一次。

## 主机自动安装

支持已核验官方制品的 Linux x64 和 macOS Intel / Apple Silicon，固定 code-server 4.141.0；按目标主机的 OS / Node CPU 架构选择原生包。Linux 要求 glibc ≥ 2.28，macOS 不使用 Linux 的 libc 检查。不兼容平台需手工配置已安装的可执行文件。自动安装需要逐主机显式授权，不能由 IM 访问链接自动授权；自定义路径不会被替换。

安装是独立、按主机去重的后台任务。先检查可复用的固定版本，远程下载失败后由 Gateway 使用可续传缓存下载，再经 SSH 传输。解包前校验固定大小、SHA256 和归档路径，运行版本/ABI 检查成功后才将新目录原子切换为正式版本。不会运行 `curl | sh`、sudo、包管理器或修改系统服务，不开放 TCP 端口。扩展与语言工具链仍单独准备。

主机工具位于用户的 `~/.local/share/codex-im-gateway/tools/code-server/`；Gateway 缓存和任务状态位于 `ide/downloads/`、`ide/installations.json`。失败不覆盖已有目录，保留缓存和 staging 便于重试；中断任务启动后显示错误，不自动重放。禁用主机、关闭该主机自动安装或改变其可执行文件会取消该主机安装，其他主机任务保留。网页每 3 秒刷新进度区，不覆盖正在编辑的表单。

## 验证

`node --test --import tsx test/ide*.test.ts` 覆盖一次性授权、配对范围/过期/撤销、安装去重与兜底传输、权限撤销、目录来源、实例复用、HTTP／WS 鉴权、CSRF 和代理凭据过滤。测试需要回环端口和临时 Unix socket 监听权限。进程测试使用明确标注的假 code-server，不代表真实编辑器或语言服务已验证。

实际启用前还需验证目标主机的官方 code-server 制品、浏览器工作台、终端、项目文件读写、所需扩展以及 HTTPS 反向代理下的 WebSocket 重连。不能只依据 `/healthz` 或 API 200 宣告上线成功。
